Defects found and fixed, with the measurement that shows it

Two selection-scope defects were found by reading the code against its own documentation on 2026-09-26, and both are now fixed, tested and re-run. They are on this page rather than in a commit message because a reader deciding how much to trust the numbers below needs to know how they were wrong first.

defectwhat it waswhat it is now evidence
Selection scope scripts/combine_newfault.py ranked candidates by the whole-grid proxy DTI while its docstring, its report field selection.scope and docs/FIELD_SELECTION_RULE.md all said the selection fold. The two disagree about which rule wins, so the shipped rule had been chosen on a number the report did not claim to use. scripts/newfault_detector.py had the same defect in its own sweep. Each candidate carries four scopes (selection, measurement, pooled01, whole); exactly one - proxy_dti_selection - selects, and an unmeasurable scope returns None and stops the run instead of scoring zero. data/evidence/combined/report.json · tests/test_combine_newfault.py · tests/test_newfault_detector.py · docs/SESSION32_PROTOCOL.md
Union holdout 2 of 5 members were fitted on the geography the union selects and measures on (seed43, seed45); every number the union reports on those folds is an in-sample number for them. Clean members: proxy_only46, seed42, seed44 Their training geography includes the folds the union uses to select and measure, so every number the union reports on those folds is optimistic for those members. Disclosed per member in every report (selection.fold_discipline) and quantified by scripts/audit_fold_discipline.py; a clean-pool control run (data/evidence/combined_clean/) repeats the whole search with only members that held both folds out. data/evidence/fold_discipline.json · tests/test_fold_discipline.py
Vote axis The sweep could only express k = 1 and k = 2 (--votes default 1,2), so the k = 3 family - the one that generalises best on the untouched fold - was not in the search space at all, and its absence was never reported. The default spans k = 1..5, an impossible k is refused by name, and the report records what was asked for (k_votes_swept) as well as what ran. data/evidence/combined/report.json · tests/test_combine_newfault.py::test_the_vote_axis_spans_k_1_to_n_and_refuses_k_above_n

What changed in the code

  • Submission reliability: direct inference now uses the same fail-loud writer as blending; read-back checks reject invalid, empty or incorrectly tiled GeoTIFFs.
  • Workflow reliability: trainer and inference exit codes are no longer hidden by a successful filtering subshell; incomplete fold matrices cannot be blended.
  • Optional DEM path: a local USGS 3DEP mosaic is reprojected to the feature grid and five well-defined derivatives are added symmetrically to train and inference. It is disabled by default until a path is supplied.

Access still required

No leaderboard claim is made. The data tab and submission form require an entrant account. Full training also needs GPU compute and external-data storage. The private test labels are intentionally withheld. The repository can fetch through a GitHub runner, train, create and validate a submission artifact; it cannot enroll an entrant, upload a submission or observe a private score.
