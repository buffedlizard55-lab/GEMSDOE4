Honest status

A green workflow is not evidence. The 6-fold ensemble run 35042805806 trained every fold for 2 h 36 min and then crashed while writing the submission (RasterBlockError: the height and width of TIFF dataset blocks must be multiples of 16). The job was reported successful, because the step piped Python into tee without pipefail, and the evidence it committed was self-incriminating: data/evidence/runs/35042805806/submission.tif is 110 bytes (a GDAL stub) and validation.log is an argparse usage dump. Fixed on 2026-09-16: a read-back-verifying writer (src/submission_io.py), pipefail on every piped step, and a commit gate that ships FAILED.json instead of a stub. The rebuilt submission is the newest run below.
The pipeline runs end to end on the real competition rasters and every number below is measured, but it is not yet competitive: the first full-scale run was a 2-epoch MobileNetV2 smoke test that scored below the trivial blanket-coverage baseline, which is recorded here as a negative result rather than dressed up. And every DTI on this page is computed against the known catalogue, which is not the scored universe (see Metric).

Cross-catalogue transfer — measured, and REFUSED

Catalogue A (SGMC structure, DOI 10.3133/ds1052) was to be emitted and scored against catalogue B (QFaults layer 21, DOI 10.5066/P9BCVRCK) on B’s code-2 pixels — the traces the training labels do not contain. The runner fetched B and rasterised it on the competition grid, and that population turned out to be one pixel wide.

Verdict: REFUSED - catalogue B is NOT independent of the training labels: 60,938 of its 60,939 in-footprint pixels (100.00 %) are already within R = 3 px of a label, leaving 1 px (0.0016 %) as a 'new fault' population - below the pre-registered minimum of 100 px and 0.50 %. Scoring against 1 pixel(s) would produce a number with no meaning, so none is reported. This is a FINDING about the two catalogues, not a bug: it means the training labels and catalogue B are the same lines in this footprint, and it is recorded with the overlap that establishes it.

Why this exits 0 and not 1. “These two catalogues are the same lines” is a finding about the data, so it is committed as a report with the overlap that establishes it (data/evidence/xcat/transfer_report.json, input sha256s included). A genuinely broken B raster — under --min-b-all-px 1,000 in-footprint pixels, i.e. empty, misaligned or miscoded — still fails the run and writes nothing, so a defect can never masquerade as a result.

What this closes. Rules §3.3 says the scored faults are a new expert set, and §11 item 1 of the executive summary asked for a prior on recall against it. That prior cannot come from a second Quaternary catalogue: none is independent of these labels, and that is now measured rather than argued. The SGMC proxy population (data/evidence/proxy/proxy_catalogue.tif, 61,664 code-2 px, 24.94% already covered by the labels) remains the only available surrogate for “faults the labels lack”, with its structural weakness intact — pre-Quaternary bedrock structure digitised from state geologic maps, not an expert interpretation of the GeoDAWN geophysics. Any future candidate catalogue must be checked for disjointness with scripts/build_proxy_catalogue.py before a transfer number is quoted.

What the numbers mean

  • DTI shaped > DTI raw on every run so far — the floor-plus-thinning step consistently helps, exactly as the metric algebra predicts.
  • FP_w dominates. The smoke model emits far too much diffuse mass. This is the single biggest lever available, and it is an output shaping problem as much as a modelling one.
  • Local scores are optimistic. They are computed against the labels used in training and are not the private test set.

Next steps, in priority order

  1. Optimise for the scored universe, not the catalogue. The scored faults are missing from labels.tif, so model selection, shaping calibration and fold weighting must be anchored on src/discovery.py diagnostics plus a spatial-block hold-out instead of catalogue DTI. This is a measurement-protocol change before it is a modelling change.
  2. Parallel 6-fold ensemble on CPU runners — implemented as the Train MC ensemble workflow (configs/config_ci_ensemble.yaml: UNet++ / DeepLabV3+ / U-Net × resnet34 at patch 256, 8-way TTA, pooled shaping calibration). The first full run is the current frontier until a GPU exists.
  3. GPU training at full capacity — configs/config.yaml (EfficientNet-B5, 10 MC splits, 60 epochs, 4 architectures) remains the config to move to; a 24 GB card turns the ~4 h CPU profile into under an hour and roughly doubles fold count.
  4. 1 m DEM derivatives from the 716 confirmed tiles — lineament and scarp signal at 100 m is the most direct physical evidence of surface faulting (code ready: src/external_data.py, scripts/download_dem_tiles.py).
  5. Frangi line-enhancement A/B on the blended map — proposed in SUGGESTIONS.md, not yet measured.
  6. Self-training with SGMC pseudo-labels — built and in flight 2026-09-19: fold 0 trained with the 61,664 px of SGMC trace the labels do not contain as training-window label mass, measured under the same spatial block holdout and paired against the no-pseudo baseline (.github/workflows/pseudo-label.yml, configs/config_pseudo_labels.yaml). The held-out arm is the leakage-safe reading.
